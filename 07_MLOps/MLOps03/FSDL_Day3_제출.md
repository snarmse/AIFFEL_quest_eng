## 1. 노트북 요약

Day 3의 핵심은 학습 코드를 만드는 것에서 끝나지 않고, 모델을 신뢰할 수 있는 시스템으로 운영하는 방법을 익히는 것이다.

- Chapter 13은 ML 테스트를 다룬다. 데이터 기댓값 테스트, 한 배치 암기 테스트, 불변성·방향성 행동 테스트를 이용해 데이터와 학습 파이프라인의 위험을 조기에 발견한다.
- Chapter 14는 문제 해결 순서인 **Make it Run → Make it Fast → Make it Right**를 설명한다. 먼저 오류 없이 실행하고, 프로파일링으로 실험 속도를 높인 뒤, 데이터·모델·하이퍼파라미터를 개선한다.
- Chapter 15는 LLM을 포함한 모델 평가와 배포 후 모니터링을 다룬다. 자동 메트릭만 사용하지 않고 LLM 평가, 인간 평가, 골든 세트, A/B 테스트를 결합하며 입력·출력·성능 드리프트를 감시한다.
- Chapter 16은 기획, 환경, 데이터, 테스트, 배포를 하나의 Full Stack ML 프로젝트 실행 계획으로 연결한다.
- 실습 예시는 KLUE YNAT 데이터와 `klue/bert-base`를 이용한 한국어 뉴스 분류 프로젝트이다. TF-IDF 베이스라인, BERT 파인튜닝, W&B 실험 추적, 테스트, FastAPI 서빙까지 전체 흐름을 보여준다.

## 2. Chapter 13 체크포인트: ML 시스템 테스트

### 문제 1. ML 테스트가 “다크 소울”이라 불리는 이유를 전통 소프트웨어와 비교하여 3가지 관점에서 설명하시오.

**답변**

1. 전통 소프트웨어는 정해진 입력에 정해진 출력이 기대되지만, ML은 확률적으로 동작해 정답과 실패 경계가 모호하다.
2. 전통 소프트웨어의 오류는 주로 코드에서 발생하지만, ML은 코드뿐 아니라 데이터 품질, 레이블, 분포 변화, 학습 설정이 서로 얽혀 오류를 만든다.
3. 전통 테스트는 통과 여부가 비교적 안정적이지만, ML 테스트는 랜덤 시드, 하드웨어, 데이터 샘플링에 따라 결과가 달라질 수 있다. 따라서 모든 것을 완벽히 증명하기보다 위험이 큰 실패를 효율적으로 감지하도록 설계해야 한다.

### 문제 2. 테스트 수트를 “분류기”로 보았을 때 오탐이 왜 위험한지 실제 사례를 들어 설명하시오.

**답변**

테스트는 버그가 있는 변경을 실패로 분류하고 정상 변경을 통과시키는 분류기와 같다. 오탐이 잦으면 정상 코드도 계속 실패하므로 개발자는 경고를 신뢰하지 않게 된다. 예를 들어 검증 F1이 매번 정확히 0.850 이상이어야 한다는 테스트는 랜덤 변동 때문에 정상 변경에서도 실패할 수 있다. 개발자가 모델을 고치는 대신 임계값을 반복해서 낮추거나 테스트를 꺼 버리면 테스트 수트 전체의 신뢰성이 무너진다.

### 문제 3. 암기 테스트가 실패했을 때 의심할 원인 5가지와 디버깅 방법을 쓰시오.

**답변**

1. **레이블 또는 배치 연결 오류**: 입력과 레이블을 직접 출력하고, 클래스 범위와 배치별 대응 관계를 확인한다.
2. **손실 함수·출력 형태 오류**: logits 형태가 `[batch, num_classes]`인지, CrossEntropyLoss에 정수 레이블을 전달하는지 확인한다.
3. **파라미터가 갱신되지 않음**: `requires_grad`, 그래디언트의 존재와 크기, optimizer에 등록된 파라미터를 확인한다.
4. **학습률이 부적절함**: 학습률을 높이거나 낮춰 loss 곡선을 비교하고, 간단한 optimizer로 재시험한다.
5. **규제 또는 학습 모드 문제**: dropout, weight decay, data augmentation을 끄고 `model.train()` 상태인지 확인한다. 또한 한 배치가 반복 사용되는지도 확인한다.

### 문제 4. 데이터 기댓값 테스트에서 “느슨한 경계”가 중요한 이유를 설명하시오.

**답변**

기댓값 테스트의 목적은 정상 데이터의 작은 변화까지 막는 것이 아니라 심각한 이상을 조기에 발견하는 것이다. 경계를 지나치게 엄격하게 설정하면 계절 변화나 새로운 표현처럼 정상적인 데이터 변화도 실패로 판단한다. 오탐이 누적되면 테스트가 무시되거나 삭제될 수 있다. 따라서 과거 분포와 업무상 허용 범위를 바탕으로 넉넉한 경계를 두고, 경고와 차단 기준을 구분하는 것이 좋다.

### 문제 5. 불변성 테스트와 방향성 테스트의 차이를 프로젝트 예시와 함께 설명하시오.

**답변**

- **불변성 테스트**는 의미를 바꾸지 않는 입력 변화에도 결과가 유지되는지 본다. 뉴스 제목의 쉼표나 띄어쓰기를 바꿔도 예측 카테고리는 같아야 한다.
- **방향성 테스트**는 의미 있는 정보를 바꾸었을 때 출력이 기대 방향으로 변하는지 본다. 예를 들어 제목을 “삼성전자 신형 반도체 공개”에서 “코스피, 반도체주 상승으로 3000선 돌파”로 바꾸면 경제 카테고리 점수가 높아져야 한다.

## 3. Chapter 14 체크포인트: 모델 트러블슈팅

### 문제 1. 왜 ML에서는 Fast가 Right보다 먼저 와야 하는가?

**답변**

ML 성능 개선에는 여러 가설을 반복 실험해야 한다. 한 번의 실험이 너무 느리면 시도할 수 있는 가설 수가 줄고, 올바른 데이터·모델·하이퍼파라미터를 찾는 데 오래 걸린다. 따라서 먼저 실행 가능한 파이프라인을 만든 뒤 병목을 줄여 반복 속도를 높여야 더 많은 근거를 바탕으로 성능을 개선할 수 있다.

### 문제 2. OOM 해결 전략 4단계와 Adam의 메모리 사용 이유를 설명하시오.

**답변**

순서는 ① 혼합 정밀도 사용, ② 배치 크기 축소, ③ 그래디언트 축적, ④ 그래디언트 체크포인팅이다. Adam은 각 파라미터 외에도 그래디언트와 1차 모멘트, 2차 모멘트 상태를 보관한다. 정밀도 설정에 따라 마스터 가중치도 유지할 수 있어 전체 학습 메모리가 파라미터 자체의 약 3~4배 이상이 될 수 있다.

### 문제 3. 프로파일링 결과에 따른 최적화 방법을 설명하시오.

**답변**

- `get_train_batch`가 60%라면 데이터 로딩이 병목이다. `num_workers`, `persistent_workers`, `pin_memory`를 조정하고 토크나이징 사전 처리·캐싱, 저장 형식 개선을 먼저 시험한다.
- `training_step`이 90%라면 모델 연산이 병목이다. 혼합 정밀도, 더 작은 모델, 입력 길이 축소, 연산 그래프 컴파일, 효율적인 attention 구현 등을 비교한다. 최적화 전후 처리량과 GPU 사용률을 다시 측정한다.

### 문제 4. 스케일링 법칙의 흐름과 비즈니스 가치를 설명하시오.

**답변**

먼저 데이터 크기나 모델 크기를 단계적으로 키운 작은 실험을 여러 번 수행한다. 각 실험의 자원과 loss를 로그 스케일에서 비교해 추세선을 만들고, 이를 목표 성능 지점까지 외삽하여 필요한 데이터·GPU 시간·비용을 추정한다. 이 방법은 대규모 학습 전에 목표 달성 가능성과 예상 비용을 판단하게 해 주므로 예산 낭비를 줄이고 투자 우선순위를 정하는 데 도움이 된다.

### 문제 5. 최근 프로젝트의 성능 저하 상황과 처방을 분석하시오.

**답변**

본 계획의 뉴스 분류 프로젝트는 아직 실제 학습 전이므로 최근 실험 결과가 없다. 예상되는 첫 문제는 짧고 모호한 제목 때문에 학습과 검증 성능이 모두 낮은 **언더피팅 또는 정보 부족**이다. 우선 오류 사례를 카테고리별로 분석하고 제목 본문 추가 가능성을 검토한다. 이후 학습률·에포크·모델 크기를 조정한다. 학습 F1만 높고 검증 F1이 낮다면 오버피팅으로 판단해 데이터 확대, 정규화, 조기 종료를 적용한다. 배포 후 특정 시기의 기사에서만 성능이 떨어지면 분포 변화로 보고 최신 데이터 수집과 재학습을 실시한다.

## 4. Chapter 15 체크포인트: 평가와 모니터링

### 문제 1. LLM을 Accuracy만으로 평가할 수 없는 이유와 추가 평가 차원 5가지를 쓰시오.

**답변**

LLM 답변은 하나의 정답 문자열만 존재하지 않으며, 정확해도 표현이나 근거가 부적절할 수 있다. 따라서 Accuracy만으로 전체 품질을 나타낼 수 없다. 추가 차원은 ① 사실성·환각 여부, ② 유창성, ③ 관련성, ④ 근거 문서에 대한 충실성·출처성, ⑤ 안전성과 편향이다. 서비스에 따라 지시 준수, 톤, 지연시간, 비용도 함께 본다.

### 문제 2. LLM-as-a-Judge의 장점, 한계와 편향 완화 방법을 설명하시오.

**답변**

장점은 많은 자유 형식 응답을 인간보다 빠르고 일관된 기준으로 평가할 수 있다는 점이다. 한계는 평가 모델 자체의 지식 오류, 특정 표현·길이·응답 순서에 대한 선호, 자기 모델 계열 선호 같은 편향이다. 완화 방법으로 평가 기준과 예시를 명확히 고정하고 답변 순서를 무작위화한 뒤, 일부 표본을 인간이 이중 평가하여 judge 점수와의 일치도를 정기적으로 보정한다.

### 문제 3. 입력·출력·성능 드리프트를 구분하고 프로젝트에서 가장 가능성 높은 유형을 분석하시오.

**답변**

- 입력 드리프트는 운영 입력의 단어, 길이, 주제 등의 분포가 학습 데이터와 달라지는 현상이다.
- 출력 드리프트는 예측 클래스 비율이나 점수 분포가 이전과 달라지는 현상이다.
- 성능 드리프트는 실제 정답 기준 Accuracy·F1 등 품질 지표가 낮아지는 현상이다.

뉴스 분류에서는 새로운 인물, 기술, 사건을 표현하는 신조어가 계속 등장하므로 입력 드리프트 가능성이 가장 높다. 이것이 특정 카테고리 예측 비율 변화와 실제 F1 저하로 이어질 수 있다.

### 문제 4. “모델은 시간이 지나면 썩는다”는 의미와 방지 시스템을 설명하시오.

**답변**

모델 파라미터가 물리적으로 변한다는 뜻이 아니라 현실의 데이터와 개념이 바뀌어 학습 당시의 관계가 더 이상 맞지 않게 된다는 뜻이다. 예를 들어 코로나19 이전의 의료 수요·검색·소비 데이터를 학습한 모델은 팬데믹 이후 급변한 패턴을 제대로 예측하지 못한다. 이를 막기 위해 입력·출력 분포 모니터링, 지연 정답 수집, 성능 대시보드, 임계값 기반 알림, 정기 또는 이벤트 기반 재학습, 새 모델 검증과 롤백 체계가 필요하다.

## 5. Day 3 통합 체크포인트

### 문제 1. 워크시트 Part A~D를 완성하시오.

**답변**

아래 6장의 ML 실행 계획서에 Part A~D의 기획, 인프라·데이터, 테스트·품질, 배포 내용을 통합해 작성하였다.

### 문제 2. 데이터 기댓값 테스트 3개, 암기 테스트 1개, 행동 테스트 2개를 설계하시오.

**답변**

- 데이터 테스트 1: 제목이 null 또는 빈 문자열이면 실패한다.
- 데이터 테스트 2: 레이블은 0~6 사이의 정수여야 한다.
- 데이터 테스트 3: 제목 길이는 2~500자 범위이며 최소 클래스 비율은 3% 이상이어야 한다.
- 암기 테스트: 규제를 끄고 8개 샘플 한 배치를 최대 30에포크 반복 학습하여 train loss가 0.1 미만인지 확인한다.
- 행동 테스트 1: 쉼표·띄어쓰기 변화 전후 카테고리가 동일해야 한다.
- 행동 테스트 2: IT 중심 문장에 증시 맥락을 강하게 추가했을 때 경제 클래스 점수가 증가해야 한다.

### 문제 3. 가장 큰 병목에 대한 가설과 검증 계획을 쓰시오.

**답변**

가장 큰 병목은 한국어 제목을 매 배치마다 토크나이징하는 데이터 전처리라고 가정한다. `Trainer(profiler="simple")`로 1에포크를 실행해 `get_train_batch`와 `training_step`의 시간 비율을 측정한다. 데이터 로딩 비율이 높으면 토큰 사전 계산과 캐싱, worker 수 변경을 각각 적용해 초당 샘플 수를 비교한다. 모델 연산 비율이 높으면 혼합 정밀도와 입력 최대 길이 128/64를 비교한다.

### 문제 4. 프로젝트를 1페이지로 요약하시오.

**답변**

한국어 뉴스 제목을 IT과학·경제·사회·생활문화·세계·스포츠·정치의 7개 범주로 분류한다. KLUE YNAT 데이터와 TF-IDF + Logistic Regression을 기준선으로 사용하고 `klue/bert-base`를 파인튜닝한다. 목표는 Macro F1 0.85 이상이며, 실제 기준선과 최종 F1은 실행 후 기록한다. 데이터 스모크 테스트, 한 배치 암기 테스트, 표현 변화 행동 테스트를 PR 및 야간 테스트로 나눈다. W&B로 loss, F1, 학습률, 시간을 추적하고 FastAPI `/classify`로 제공한다. 운영에서는 입력 단어 분포, 예측 클래스 비율, 레이블이 확보된 표본의 Macro F1을 감시한다.
